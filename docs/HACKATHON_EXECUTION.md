# 48-Hour Execution Plan

> Historical execution plan, not current completion status: the live app and three scientific cases were completed later on November 14. See docs/PROJECT_STATUS.md.

## Before event

Pre-hackathon research may determine:
- valid case-study candidates;
- data access mechanics;
- product structure;
- UI prototype;
- scientific baseline.

Follow event rules regarding what code/assets may be prepared in advance.

## During build

### Phase 1 — prove pixels
Goal: one compatible scene pair loaded and visualized.

### Phase 2 — prove change
Goal: generate a defensible change feature.

### Phase 3 — classify
Goal: derive an inundation-change mask and area statistics.

### Phase 4 — validate
Goal: compute at least one real metric against an independent reference.

### Phase 5 — productize
Goal: expose a stable API/artifact catalog and map UI.

### Phase 6 — polish story
Goal: prepare a short demo where every visual supports the scientific narrative.

## Stop conditions

Cut stretch goals if:
- base classification is not validated;
- map performance is poor;
- scene provenance is missing;
- UI cannot explain one case clearly.

One excellent case beats five broken cases.
