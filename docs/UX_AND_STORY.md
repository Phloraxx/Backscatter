# UX and Demo Story

## Design objective

Make radar science understandable without making it childish.

## Visual direction

Backscatter should feel:
- technical;
- restrained;
- premium;
- map-first;
- evidence-driven.

Avoid:
- generic blue space gradients;
- excessive glassmorphism;
- decorative 3D Earth if it delays the useful map;
- dashboard clutter.

## Demo sequence

1. Open on a curated event.
2. Show the optical/cloud problem if relevant.
3. Reveal the NISAR observation.
4. Swipe between dates.
5. Toggle change layer.
6. Show newly inundated area.
7. Click one hotspot.
8. Show measurement evidence.
9. Show validation metric.
10. Explain that the same pipeline can transfer to other regions.

## Main UI

Suggested layout:
- full-screen map;
- compact top brand/navigation;
- date-pair controller;
- vertical or horizontal layer switcher;
- evidence panel on selection;
- bottom timeline / acquisition strip.

## Language

Use:
- "probable inundation";
- "measured backscatter change";
- "consistent with";
- "confidence";
- "observation interval."

Avoid:
- "NASA detected a flood";
- "AI knows";
- "100% accurate";
- "real-time" unless it truly is.
